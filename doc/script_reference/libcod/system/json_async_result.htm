json_async_result( <jobId> )

Module: System

Summary:

Claims and frees a finished async job. For a json_load_async job: returns the parsed GSC value (or undefined if the worker errored). For a json_save_async job: returns 1 on a successful write, 0 otherwise.

If the jobId is unknown, or the job is still pending, returns undefined and leaves the job in place; you can poll json_async_done() again.



Example:

loadJob = json_load_async("stats/big.json");
// ... time passes, polling json_async_done() ...
v = json_async_result(loadJob);
if(isDefined(v))
    iprintln("loaded " + v["records"].size + " records");
else
    iprintln("load failed");



Required Args:

  • 1 : <jobId> The integer returned by json_load_async or json_save_async.

Returns:

For a load job: the parsed value (struct/array/string/number) on success, undefined on error.
For a save job: 1 on success, 0 on error.
For an unknown id or a still-pending job: undefined (the job is left in place; safe to retry later).


Notes:

  • A successful claim (status != PENDING) UNLINKS and FREES the job; calling again with the same id returns undefined.
  • Always claim every jobId you got from json_load_async / json_save_async or the job leaks. Best practice is to drain inside a periodic polling loop.
  • The GSC-value conversion (for load jobs) runs on the main thread when you call this; for very large parsed trees this is the unavoidable cost of getting the data into GSC, but it's still much faster than parsing + reading from disk.
